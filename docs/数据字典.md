# PromptWorks 数据字典（产品视角，面试版）

> 用途：AI 产品经理面试讲法。核心是"数据怎么支撑产品闭环"，不是字段清单。
> 技术字段细节只作为背景参考，不背。

---

## 一、产品一句话

**给 AI 应用团队一个 Prompt 质量管理工作台**：把"写完就用"的散落 Prompt，变成可版本化、可批量测试、可 AI 评分、可持续优化的资产。

## 二、产品闭环（面试主线，5 步背熟）

```
1. 管理   把 Prompt 资产化：分类、标签、版本迭代
2. 测试   配一个评测任务：选版本 × 选模型 × 选参数 × 选样本
3. 批跑   引擎自动展开所有组合，真实调用 LLM，产生输出
4. 评分   AI 评估模型逐条打分（4 维度 + 理由）
5. 优化   基于低分问题生成改写建议，沉淀为新版本 → 回到 1
```

**一句话总结价值**：把"Prompt 靠感觉调"变成"靠数据迭代"，每次优化都有评分对比可查。

## 三、每个环节的数据视角（PM 讲法，不是字段）

| 环节 | 产生什么数据 | 产品上怎么用 | 面试点 |
|---|---|---|---|
| 管理 | Prompt 资产 + 版本历史 | 列表页展示、版本对比、回滚 | 内容只存版本表，主表是指针 → "可追溯、可回滚" |
| 测试 | 测试任务 + 组合单元 | 配置页：勾版本/模型/参数/样本 | 1 个任务展开 N 个组合 = 批量测试的本质 |
| 批跑 | 实验记录 + 真实输出 | 进度页：看跑到哪、失败重试 | 每组合多轮跑（rounds）→ 测稳定性 |
| 评分 | 4 维分数 + 理由 | 评分页：总分/维度分/低分问题 | 评分理由让"为什么低分"可解释 |
| 优化 | 改写建议 + 验证计划 | 优化工作台：一键沉淀新版本 | 建议落地成新版本 → 闭环成立 |

## 四、4 维评分体系（核心产品决策，必须能讲）

| 维度 | 回答什么问题 | 例子 |
|---|---|---|
| 准确性 | 输出是否符合事实/要求 | 客服话术是否解决了用户问题 |
| 完整性 | 有没有漏信息 | 是否覆盖了用户所有诉求点 |
| 清晰度 | 表达是否清楚无歧义 | 用户能不能看懂 |
| 稳定性 | 同一 Prompt 多次跑结果波动大不大 | 5 轮跑下来分数是否忽高忽低 |

**为什么选这 4 维**：覆盖了 Prompt 质量的 3 个层面——结果对不对（准确性）、全不全（完整性）、表达好不好（清晰度），外加一个运营视角最关心的"线上效果稳不稳"（稳定性）。面试可补充：维度可配置，不同业务场景可以换维度。

## 六、面试问答预演（PM 视角，背熟）

**Q1：为什么拆成"任务/单元/实验/评分"这么多层？**
A：任务=测试计划，单元=一个具体组合，实验=一次真实执行，评分=AI 打分。分层的好处：改配置不动历史结果、多轮可对比、评分可单独重跑。产品上就是"一次配置，批量执行，逐条评估"。

**Q2：多模型对比怎么做的？**
A：同一个任务下建多个单元，各指定不同模型，跑同一批样本，统一评分。分析模块按单元分组，直接看哪个模型又快又好又稳。这就是 A/B 实验的数据基础。

**Q3："稳定性"怎么量化？**
A：同一组合设多轮（比如 5 轮），每轮独立评分，看分数波动。波动小=稳定。这是"线上效果稳不稳"的产品化。

**Q4：为什么接 DeepSeek 做默认评测模型？**
A：评测要跑大量样本，成本敏感。DeepSeek 走 OpenAI 兼容协议，接一个 provider 全平台可用，且国内访问稳定、成本低。这是"评测成本要可控"的产品决策。

**Q5：怎么证明这个产品有用？**
A：跑真实对比：优化前 vs 优化后，同一批样本评分提升（比如稳定性 +X%）。所有数字可复现，因为测试配置、输出、评分全都在库里。
